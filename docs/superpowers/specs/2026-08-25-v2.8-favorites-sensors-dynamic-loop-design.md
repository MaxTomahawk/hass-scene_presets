# Scene Presets v2.8 design

## Scope

This release contains two approved changes:

1. Expose persistent per-user Scene Presets favorites through normal Home Assistant sensor entities and allow favorite actions to target an explicit Home Assistant user.
2. Make dynamic scenes lifecycle-safe and improve manual-change detection so long-running color transitions do not stop themselves while genuine external color changes still stop the scene.

No custom Lovelace card is added.

## Per-user favorites sensors

- Keep `FavoritesStore` as the source of truth for `user_id -> favorite preset IDs`.
- Add a sensor platform to the existing config entry.
- Create one sensor per Home Assistant user after that user has had at least one real favorite. Opening the Scene Presets page with an empty migrated favorites list must not create a sensor.
- Once created, a user's sensor remains available even when their favorites later become empty.
- Persist which users have sensors so the entities are restored after Home Assistant restart.
- Use a stable unique ID based on the Home Assistant user ID, not the display name.
- Sensor state is the number of favorites.
- Sensor attributes include `user_id`, `user_name`, `favorite_ids`, and `favorite_names`.
- Favorite storage mutations notify the corresponding sensor immediately.
- Existing WebSocket behavior remains self-user-only.

## Favorite actions

- Add optional `user_id` to `get_favorites`, `is_favorite`, `set_favorites`, `add_favorite`, `remove_favorite`, and `toggle_favorite`.
- If `user_id` is omitted, use `call.context.user_id` as today.
- If neither exists, return a validation error.
- A call with an explicit `user_id` must resolve to a real Home Assistant user.
- An authenticated non-admin user may only target their own user ID.
- An authenticated admin may target another user.
- An automation/service call with no user context may target a user only by supplying an explicit valid `user_id`.
- Add `set_favorites` because it is the natural backend counterpart of the existing WebSocket `set_favorites` command.

## Dynamic scene lifecycle

- A dynamic scene background task must never silently die while the manager still reports `running: true`.
- The manager/scenes expose runtime status sufficient to diagnose a stopped task, including a stop reason and last error when relevant.
- Exceptions from one iteration are logged and cause deterministic scene cleanup rather than a zombie scene.
- Add tests that execute at least five real loop iterations and prove that the loop continues until explicitly stopped.
- `apply_preset()` must not mutate the dynamic scene's stored target list; shuffle a local copy.
- Bound retained scene context IDs so an indefinitely running scene does not leak memory.

## Manual-change detection

- Turning any target light off stops the dynamic scene immediately when `stop_on_manual_change` is enabled.
- Brightness-only changes never stop the scene.
- A color change with a known scene context is ignored.
- Explicit Home Assistant user color actions with an unknown context stop immediately.
- Replace the fixed two-second contextless grace heuristic with per-light expected-move tracking.
- For every scene-issued move, track target color, start color, color mode, command time, and transition duration per light.
- A contextless state report during the expected transition is accepted only when it is compatible with progress toward the scene-issued target (including reaching the target within tolerance). A report that diverges from the expected move stops the scene.
- State reports after the expected transition window are not accepted merely because they are contextless.
- Expected-move tracking supports the color modes already handled by the integration: XY, color temperature, HS, RGB, RGBW, and RGBWW. For commands emitted as XY or color temperature, compare against the corresponding effective state representation.
- Service-action intent may be used as additional evidence for external Home Assistant color actions, but state-based expected-move tracking remains the fallback for physical/device-side changes.
